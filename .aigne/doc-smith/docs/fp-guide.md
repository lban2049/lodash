# Functional Programming Guide

The `lodash/fp` module provides a functional programming approach to Lodash, offering immutable, auto-curried, iteratee-first, and data-last methods. This style promotes creating reusable and composable functions, which can lead to cleaner and more predictable code.

To get started, simply import methods from `lodash/fp`:

```javascript Getting Started with lodash/fp icon=logos:javascript
// Load the FP build for immutable auto-curried iteratee-first data-last methods.
import fp from 'lodash/fp';

// Cherry-pick methods for smaller bundles.
import map from 'lodash/fp/map';
import curryN from 'lodash/fp/curryN';
```

## Core Principles

The functional programming variant of Lodash is built on several key principles that differentiate it from the standard Lodash library.

### 1. Immutability

FP methods do not mutate the data you pass to them. Any method that would normally change the input data, such as `_.set` or `_.pull`, instead returns a new, modified object or array, leaving the original untouched.

This is achieved by wrapping methods that are known to cause mutations. For example, array methods like `fill`, `pull`, and `reverse`, and object methods like `assign`, `defaults`, and `merge` are converted to their immutable counterparts.

```javascript Immutability Example icon=logos:javascript
import { set } from 'lodash/fp';

const originalObject = { 'a': [{ 'b': { 'c': 3 } }] };

// 'set' returns a new object instead of modifying the original.
const newObject = set('a[0].b.c', 4, originalObject);

console.log(originalObject.a[0].b.c); // => 3
console.log(newObject.a[0].b.c);      // => 4
```

### 2. Auto-Currying

All methods in `lodash/fp` are automatically curried. This means you can call a function with fewer arguments than it expects, and it will return a new function that waits for the remaining arguments. This is incredibly powerful for creating specialized functions.

```javascript Auto-Currying Example icon=logos:javascript
import { map, add } from 'lodash/fp';

// Create a specialized 'addOne' function by partially applying 'add'.
const addOne = add(1);

// Create a specialized 'incrementAll' function by partially applying 'map' with 'addOne'.
const incrementAll = map(addOne);

const numbers = [1, 2, 3];
console.log(incrementAll(numbers)); // => [2, 3, 4]
```

### 3. Iteratee-First, Data-Last (Argument Reordering)

To facilitate currying and function composition, the arguments of most Lodash methods are rearranged. The data (like an array or object) is typically the last argument, while the function to apply (the iteratee) is first.

This data-last approach makes it easy to build up pipelines of operations.

- **Standard Lodash:** `_.map(collection, iteratee)`
- **FP Lodash:** `fp.map(iteratee)(collection)`

This reordering is applied consistently. For a function like `_.get(object, path, defaultValue)`, the FP equivalent is `fp.get(path, object)` or with a default value, `fp.getOr(defaultValue, path, object)`.

### 4. Placeholder for Currying

Lodash FP provides a special placeholder value, `_` (accessible via `fp.placeholder`), to allow supplying arguments out of order when currying. This is particularly useful when the data argument is not the last one you want to provide.

```javascript Placeholder Example icon=logos:javascript
import fp from 'lodash/fp';

const numbers = [10, 20, 30, 40, 50];

// Create a function that subtracts each number in an array from 100.
// The placeholder `_` allows us to specify the second argument of `subtract` first.
const subtractFrom100 = fp.subtract(100);
const result = fp.map(subtractFrom100, numbers);
console.log(result); // => [90, 80, 70, 60, 50]

// Alternatively, using the placeholder directly with map:
const subtractAllFrom100 = fp.map(fp.subtract(_, 100));
const invertedResult = subtractAllFrom100(numbers);
console.log(invertedResult); // => [-90, -80, -70, -60, -50]
```

## Method Aliases & Compatibility

To provide a familiar experience for developers coming from other functional libraries like Ramda, `lodash/fp` includes numerous aliases. This reduces friction and makes the library more intuitive.

Key aliases include:

| Lodash FP Name | Alias(es) |
| :--- | :--- |
| `forEach` | `each` |
| `forEachRight` | `eachRight` |
| `toPairs` | `entries` |
| `head` | `first` |
| `flowRight` | `compose` |
| `includes` | `contains` |
| `isEqual` | `equals` |
| `get` | `prop`, `path`, `property` |
| `set` | `assoc`, `assocPath` |
| `placeholder` | `__` |
| `stubFalse` | `F` |
| `stubTrue` | `T` |
| `every` | `all` |
| `some` | `any` |

## Custom Conversions

The entire `lodash/fp` module is generated by converting the standard Lodash library using a powerful `convert` function. This function allows for fine-grained control over the conversion process through an options object. You can use this to create your own customized FP builds.

The main conversion options are:

- **`cap`** (boolean): Toggles capping of iteratee arguments. Defaults to `true` to prevent issues with functions like `parseInt` receiving extra arguments.
- **`curry`** (boolean): Toggles auto-currying. Defaults to `true`.
- **`fixed`** (boolean): Toggles fixing function arity. Defaults to `true`.
- **`immutable`** (boolean): Toggles immutable operations. Defaults to `true`.
- **`rearg`** (boolean): Toggles argument reordering (data-last). Defaults to `true`.
